# Mac App Store readiness audit (2026-10-17)

Read-only investigation round (Sonnet 5.5) on main at 6c55a9c. Probe sources are in `probe/`: ad-hoc signed CLI binaries,
sandboxed and unsandboxed. Evidence tags: **[code]** read in the repo, **[probe]** run here, **[doc]** quoted from Apple,
**[unverified]**.

증거 표기: **[code]** 레포에서 읽음, **[probe]** 내가 샌드박스 바이너리로 실행함, **[doc]** Apple 페이지에서 가져옴, **[unverified]** 확인 못 함. 성능 라운드가 아니라서 박스 lease는 쓰지 않았고 리소스 타임라인은 해당 없음입니다.

# 0. 판정

**MAS 빌드는 가능합니다.** 샌드박스에서 불가능한 것은 `command` 엔진 하나와 자동 업데이트뿐입니다. 필요한 작업은 entitlement 4개, 코드 변경 2건(내보내기 폴더 bookmark, Updates 제거), 스토어 쪽 준비입니다.

우선순위 높은 블로커:
1. **Updates 제거.** GitHub 일일 체크, DMG로 보내는 배너, install-count 다운로드는 2.4.5(vii) 위반입니다.
2. **내보내기 폴더.** `~/Documents/Mwoyeo`가 컨테이너 안으로 들어가 사용자에게 보이지 않습니다.
3. **`command` 엔진.** `posix_spawn`이 샌드박스에서 실패합니다 [probe]. 2.5.2 위험도 있어서 MAS에서는 뺍니다.
4. **`network.client` 누락.** 빠지면 localhost Ollama를 포함한 모든 엔진이 죽습니다 [probe].
5. **스토어 쪽 공백.** 개인정보처리방침 URL이 없고(5.1.1(i)), 클라우드 엔진 동의 UI가 약하고(5.1.2(i)), MI-GAN 가중치 라이선스가 미해결입니다(`tools/inpaint/BENCH.md:70-71`, 이미 "legal should confirm"으로 표시됨).

공수는 Sonnet 코드 라운드 3개와 접근성 라운드 1개, 그리고 lead/user가 하는 스토어 작업입니다.

# 2. 심사 가이드라인 위험

가이드라인 번호는 https://developer.apple.com/app-store/review/guidelines/ 기준입니다. 자동 업데이트 금지는 **2.4.5(vii)**이고, (iv)는 "추가 코드/리소스 다운로드" 조항입니다.

- **업데이트 체크: 높음.** 2.4.5(vii) "They must use the Mac App Store to distribute updates; other update mechanisms are not allowed."
  - `Updates`, `UpdateBanner`, 정보창의 업데이트 행, `SettingsView.swift:511-512`의 문구를 컴파일에서 뺍니다.
  - install-count 다운로드(`Updates.swift:67-75`)도 같이 빠집니다.
  - GitHub 링크는 유지하되 "Release Notes"는 DMG가 달린 releases 페이지 대신 docs 페이지로 돌립니다.
- **임의 명령 실행: 높음.** 2.5.2 "may not ... download, install, or execute code which introduces or changes features". 샌드박스에서도 실패합니다.
  - "Command" 행(`EngineSheet.swift:113`)을 숨깁니다.
  - 붙여넣기 import(`:205-207`, `EngineShare.decode`)에서 거부합니다.
  - 디스패치 지점(`EngineClient.swift:64`)에서 거부합니다.
  - HTTP 템플릿은 데이터(URL, 헤더, `{{key}}`)라 낮음입니다.
- **다운로드/모델: 낮음.** 앱이 직접 받는 것은 없습니다. 언어팩과 Apple Intelligence 모델은 macOS가 받고 MI-GAN은 번들입니다. Application Support 폴백만 제거합니다.
- **사용자 API 키 + 제3자 AI: 중간.** 5.1.2(i) "You must clearly disclose where personal data will be shared with third parties, including with third-party AI, and obtain explicit permission before doing so."
  - 지금은 `EngineSheet.swift:241`의 캡션("Text the lens reads is sent to \(host).")뿐입니다.
  - 로컬이 아닌 호스트에는 명시적 확인(체크박스나 알림)을 추가하고, 방침에 제공자를 적습니다.
  - BYO-key 자체를 막는 규칙은 못 찾았습니다.
- **화면 녹화: 낮음.** 2.5.14 "explicit user consent and ... clear visual and/or audible indication".
  - TCC 프롬프트가 동의이고 렌즈 링이 표시입니다.
  - 프레임은 저장하지 않고 transcript/이미지 저장은 opt-in입니다. Notes for Review에 명시합니다.
- **오버레이/번역: 해당 조항 없음.** 이를 직접 다루는 가이드라인은 못 찾았습니다.
  - 5.2.1(제3자 자료)은 마케팅 에셋에 적용됩니다. 스크린샷과 프리뷰는 `demo/*.html`로 만들고 실제 채팅 앱이나 만화는 쓰지 않습니다.
  - 2.3.4 "previews may only use video screen captures of the app itself."
- **전력: 낮음.** 2.4.2. 정지 화면은 거의 0이라는 README 주장을 뒷받침할 수치를 준비해 둡니다.
- **심사 데모: 중간.** 2.1. 심사 Mac에 Screen Recording 권한, 언어팩, Apple Intelligence가 없을 수 있습니다.
  - Notes for Review에 설명합니다.
  - "권한 후 재실행" 단계가 결함처럼 보일 수 있으니 서명 빌드에서 `CGPreflightScreenCaptureAccess`가 재실행 없이 바뀌는지 테스트합니다.
- **개인정보처리방침: 공백.** 5.1.1(i) "link to their privacy policy in the App Store Connect metadata field and within the app".
  - 레포와 `AboutView`(`SettingsView.swift:491-506`) 어디에도 없습니다.
  - 필요한 것은 호스팅 페이지와 앱 내 링크입니다.
  - 내용에는 기본 on-device, 사용자가 입력한 호스트로만 가는 줄 텍스트, 전면 앱 bundle id의 로컬 보관, 분석 없음, 삭제 방법을 담습니다.
- **프라이버시 라벨: 결정 필요.**
  - Apple: "'Collect' refers to transmitting data off the device in a way that allows you and/or your third-party partners to access it for a period longer than what is necessary ..." (https://developer.apple.com/app-store/app-privacy-details/)
  - Updates를 빼면 **"Data Not Collected"**가 방어 가능합니다. Presentify가 같은 라벨을 씁니다.
  - 사용자가 지정한 클라우드 엔드포인트는 Apple 페이지가 다루지 않습니다 [unverified]. "third-party partners"는 "code you've added"로 정의되어 있어 사용자가 입력한 엔드포인트는 해당하지 않아 보입니다.
  - 심사에서 이견이 나오면 "Other User Content, not linked, App Functionality"로 후퇴합니다. 라벨은 새 빌드 없이 수정 가능한 것으로 알고 있지만 [unverified].
- **수출 규정:** `ITSAppUsesNonExemptEncryption = NO`를 추가합니다(HTTPS만 사용).
- **Privacy manifest:** [doc] required-reason API 문서가 "iOS, iPadOS, tvOS, visionOS, or watchOS"만 나열해서 macOS는 선택입니다. 추가하는 것은 싸니 권합니다.
- **라이선스(법무): 중간.** Places2 가중치의 비상업 조건은 repo에 이미 표시돼 있습니다. Places2 페이지는 connection refused로 못 열었습니다 [unverified]. featuring되면 노출이 커집니다.

# 3. 빌드 배관 (한 타깃, 두 flavour)

- Swift package traits도 가능하지만 Xcode가 로컬 패키지 traits를 다루는지는 [unverified].

# 4. Featuring

**방식.** [doc] https://developer.apple.com/app-store/getting-featured/ : "While there's no checklist of requirements for getting featured on the App Store, our team considers the following factors:" 항목은 User experience, UI design, Innovation, Uniqueness, Accessibility, Localization, App Store product page(스크린샷/프리뷰/설명 + "positive ratings and reviews")입니다.

**추천 양식은 존재합니다.** App Store Connect > 앱 > Featuring > Nominations. 필드(https://developer.apple.com/help/app-store-connect/manage-featuring-nominations/nominate-your-app-for-featuring/ 와 CSV 템플릿 페이지):
- Name 60자
- Type: `New Content` / `App Enhancements` / `App Launch`
- Description 1,000자("state the purpose and priority level")
- Publish Date(날짜 또는 범위)
- Platforms: `macOS` 선택 가능
- Countries/Regions
- Localizations(자동)
- Supplemental URL 최대 5개
- Helpful Details 500자("accessibility, inclusivity ...")

제출 가능 역할은 Account Holder/Admin/App Manager/Marketing입니다. 리드타임은 featuring 페이지가 "minimum of two weeks", 도움말이 "minimum lead time of 3 weeks", 폭넓은 검토를 원하면 3개월 전입니다. 앱 레코드가 먼저 있어야 합니다. Mwoyeo는 **App Launch + macOS**입니다. 선정 검토 시 Apple이 프로모션 에셋을 이메일로 요청합니다.

**맞는 특성**
- Innovation: Translation, Foundation Models, Vision, Core ML을 모두 on-device로 씁니다. 가장 강한 카드입니다.
- 프라이버시: Updates를 빼면 "Data Not Collected"가 가능합니다.
- 현지화: UI 12 로케일(en + de, es, fr, it, ja, ko, pt-BR, ru, uk, zh-Hans, zh-Hant), 문자열 294개.
- 디자인: Liquid Glass(`.glassEffect` 7곳, `MenuPanel.swift`, `OnboardingView.swift`)와 Apple Intelligence 색 렌즈 링.

**구체적 공백**
1. **접근성이 얇습니다.** VoiceOver/키보드 패스가 필요합니다.
   - 앱 전체에서 accessibility 주석이 13개뿐입니다.
   - 렌즈 크롬(`RegionFrameWindow.swift`)과 `OverlayHostView`는 접근성 요소를 노출하지 않습니다.
   - 렌즈 배치는 포인터 드래그가 필요합니다(`RegionPicker.swift`).
   - "breathing" 글로우(`RegionFrameWindow.swift:251-270`)는 Reduce Motion을 무시하고, 앱 어디에도 `accessibilityDisplayShouldReduceMotion` 확인이 없습니다.
   - Accessibility Nutrition Labels는 지금은 자율이지만 "over time, you'll be required to share accessibility support details". 라벨 주장 조건은 "users must be able to complete all of the common tasks of your app using that feature"(https://developer.apple.com/help/app-store-connect/manage-app-accessibility/overview-of-accessibility-nutrition-labels/)이고 Mac에는 Larger Text 라벨이 없습니다.
   - v1은 검증된 것만 주장합니다.
2. **12개 로케일 제품 페이지.** 이름/부제/설명/키워드/스크린샷을 로케일마다 준비합니다. 베트남어와 태국어는 번역 대상이지 UI 언어가 아닙니다.
3. **출시 시점에는 평점과 리뷰가 없습니다.** 페이지가 평가 요소로 적은 항목입니다.
4. **스크린샷(Mac, 필수).** 16:10의 1280x800, 1440x900, 2560x1600, 2880x1800 중 하나. 1~10장, jpeg/png, alpha 없음. 2880x1800을 권합니다. 2.3.3 "Screenshots should show the app in use".
5. **프리뷰 영상(선택, 효과 큼).** 1920x1080 가로, 15~30초, 30fps 이하, H.264 10-12 Mbps, mov/m4v/mp4, 500MB 이하, 스테레오 AAC 오디오(256kbps), 로케일당 3개까지. 레포에는 GIF뿐(`docs/media/hero.*.gif`)이라 MP4를 새로 캡처해야 합니다. 스펙 URL은 https://developer.apple.com/help/app-store-connect/reference/app-information/app-preview-specifications 입니다.
6. **메뉴바 전용 앱의 첫인상.** `LSUIElement`라서 첫 실행 창과 메뉴 패널이 첫인상 전부입니다. 온보딩의 "재실행" 안내를 테스트로 없애야 합니다.
7. **타이밍.** 출시일 최소 3주 전, 폭넓은 검토는 3개월 전에 넣습니다.
