## The one worse cell: p12-s1 spill 0 -> 2, and the merged block behind it

The kept block of p12-s1 is a reader block that glues the last prose line of the left column ("ch becomes pL (Eq. 14, first case). A second
event") to the three command lines of Listing 4 in the right column: `$ cd ../paper-bench && ./...`, `$ ./run.sh <Mwoyeo binary> ...`,
`$ cd ../usecase-bench && ...` (the trace's ocr-block 11 of p12-s1.err; core 2,22 1256x975, the block P1 reported as the main papers gap).
The prompt rule (C1's isPrompt, `^\s*\$\s+\S`) fires on the three command lines and the whole block is kept as a terminal. Keeping the commands
is right; the one prose line that rides along stays English (one line not translated). It is the "$ " prompt risk of the backlog,
measured on the paper instead of on the use cases: here it is a reader failure (two columns in one block) and not a prose line starting
with "$ 20".
Effect on the metrics: in main, 17 blocks of this crop are clipped (a text rectangle of size 0), 20 pairs are cross-column (this block holds
the others) and 3 are big; with the block kept as written those fall to 1, 0 and 0, the other blocks get their own rectangles, and two of
them (the translated lines "frame at to = 1.045s ..." and "firmed a shift. The report ..." in p12-s1.out) are drawn at 30.6 and 28.4 px with a text rectangle wider than their
column: spill 2 (text 725 and 696 px against a core of 599 and 607). So the spill is the layout's own overflow, shown once the block that
hid it is gone. Nothing was tuned: the rule is C1's, and the bench is run as it is.
Options for the lead: (1) accept and record (clipped -16, cross -20, big -3 in that crop, spill +2; one prose line left English); (2) in
CodeKeep, never keep a block whose rectangle spans more than one column of text (the reader's failure, not a listing) -- the block would then
be translated as today; (3) wait for the reader fix (D1 page block), which removes the merged block itself. Each is a follow-up with its own
FAIL-first; this round changes none of them.

   split and the label rule had already measured the same rectangles. Before the memo, the same renders measured 165 ms (p3, 107 lines) and
   53 ms (p7, 104 lines); the memo also removes the old duplicate measurements, so the pass does less work than main did.

   cost is the text evidence (`CodeRegion.features`, about 16 regular expressions per line with Swift Regex) of every group, linear in the
   blocks (a standalone Release build of CodeRegion.swift: 86 ms for 50 prose blocks, 173 ms for 100, 345 ms for 200, 687 ms for 400; the
   geometry part is under 1 ms). Cheap necessary tests before each expression (a comment needs `/`, `*`, `-`, `#` or the arrow at the start; a
   prompt needs one of `$ % # > ❯`; a diff line `@@`, `+`, `-`; an assignment `=`) would cut it by a large factor without changing a
   verdict; they are not in this round (CodeRegion.swift is C1's, and its `verdict` function is cut by line number into the paper's
   listing, tools/paper-own/mwoyeo-method/build.sh).
